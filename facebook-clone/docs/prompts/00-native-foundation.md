# Astra prompt: native iOS foundation

> Accepted implementation scope: responsive web + native iOS through Expo Go. Android testing/distribution is deferred. See [architecture and extension contract](../ARCHITECTURE.md).


Build the **native mobile shell and platform adapters** after the shared seed/domain interface is stable. Read `docs/MOBILE_APP_SPEC.md`, `docs/CONTENT_AND_INTERACTIONS.md`, `docs/VISUAL_SPEC.md`, and the [shared foundation prompt](00-shared-shell.md). Inspect the actual Expo scaffold and installed packages before editing. The phone browser view is a separate web target; this prompt requires React Native screens running on iOS.

Use the local [2026 phone Home](../references/images/mobile-home-2026-ui.png), [Menu](../references/images/mobile-menu-2026-ui.png), [Profile](../references/images/mobile-profile-2026-ui.png), [Friends](../references/images/mobile-friends-2026-ui.png), [Settings](../references/images/mobile-settings-2026-ui.png), and [App Store Marketplace](../references/images/mobile-marketplace-2026-ui.png) crops to establish native hierarchy and density. Do not copy teaching-slide frames, source people's content, or the App Store marketing border into runtime UI.

Create a native five-tab shell in the fixed order **Home, Friends, Marketplace, Notifications, Menu**. Keep the bottom tabs clear of the home indicator/navigation bar and use native stack/sheets for Profile, search, stories, post/listing details, chats, composer, and Settings subsections. Native Back/close dismisses the current detail/sheet first; iOS back gestures work predictably. Keep scrollable content and text inputs clear of the keyboard and system bars. Every visible tile/tab/icon has a local destination. Share the demo's route IDs and active theme with web, but use native components where platform layout differs.

Create the native persistence adapter for the **same versioned overlay** used on web, backed by a small persistent key-value store such as [Async Storage](https://docs.expo.dev/develop/user-interface/store-data/). Hydrate before showing final counts/theme so the app does not flash incorrect seed state. Validate saved JSON, handle write failures visibly, and reset only the demo key plus its owned user-photo files. Seed images are bundled local assets keyed from the shared seed. For user photo posts, select from the photo library with [ImagePicker](https://docs.expo.dev/versions/latest/sdk/imagepicker/), resize/compress if needed, copy into persistent app documents with [FileSystem](https://docs.expo.dev/versions/latest/sdk/filesystem/), and store a URI rather than base64. Picker cancel and permission/failure states leave the draft intact.

Apply the shared light/dark tokens with platform system fonts. Provide accessible labels, touch targets, keyboard avoidance, and reduced-motion behavior. Confirm native Home and Menu launch on an iOS simulator/device before page agents build the remaining native screens. A mobile-width web browser preview is insufficient. Leave stable navigation and storage interfaces for the page agents and record exact native run commands for the final README.
